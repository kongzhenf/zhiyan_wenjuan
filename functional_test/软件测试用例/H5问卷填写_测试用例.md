## 一、通过链接获取问卷内容（FR-027）

### TC-FILL-001: 正常获取已发布问卷内容
- **关联需求**: FR-027
- **前置条件**: 管理后台已创建并发布一份问卷，access_code 为 `VALID_LINK_001`，问卷包含单选、多选、文本、评分、下拉共5道题目
- **测试步骤**:
  1. 发送 HTTP 请求:
     ```
     GET http://10.32.129.153:8082/api/fill/VALID_LINK_001
     Content-Type: application/json
     ```
  2. 接收响应并验证返回内容
- **预期结果**:
  - HTTP 状态码: `200`
  - 响应体 `code` 字段: `200`
  - 响应体包含 `title`（问卷标题，非空字符串）
  - 响应体包含 `description`（问卷描述）
  - 响应体包含 `questions` 数组，长度为5
  - 每个 question 对象包含 `questionId`、`type`、`title`、`required` 字段
  - type 为 `radio`/`checkbox`/`dropdown` 的题目包含 `options` 数组，每个 option 含 `id` 和 `label`
  - type 为 `rating` 的题目包含 `maxRating` 字段
- **优先级**: P0
- **测试类型**: 正常流程

---

### TC-FILL-002: 获取包含所有题型的问卷并验证数据结构完整性
- **关联需求**: FR-027
- **前置条件**: 管理后台已创建并发布一份问卷（access_code: `FULL_TYPE_LINK`），包含以下题目: 单选题(radio)×1、多选题(checkbox)×1、文本输入题(input)×1、评分题(rating)×1、下拉选择题(dropdown)×1
- **测试步骤**:
  1. 发送 HTTP 请求:
     ```
     GET http://10.32.129.153:8082/api/fill/FULL_TYPE_LINK
     Content-Type: application/json
     ```
  2. 解析响应体中的 `questions` 数组
  3. 逐一验证每种题型的数据结构
- **预期结果**:
  - HTTP 状态码: `200`
  - 响应体 `code` 字段: `200`
  - radio 类型题目: `options` 数组长度 ≥ 2，每个 option 包含 `id`(非空) 和 `label`(非空)
  - checkbox 类型题目: `options` 数组长度 ≥ 2，每个 option 包含 `id`(非空) 和 `label`(非空)
  - input 类型题目: 不含 `options` 字段（或为空数组）
  - rating 类型题目: 包含 `maxRating` 字段，值为正整数
  - dropdown 类型题目: `options` 数组长度 ≥ 2，每个 option 包含 `id`(非空) 和 `label`(非空)
  - 所有题目均包含 `questionId`（Long类型）、`title`（非空字符串）、`required`（布尔值）
- **优先级**: P0
- **测试类型**: 正常流程

## 决策记录

| 编号 | 决策内容 | 理由 |
|------|---------|------|
| D-01 | HTTP状态码预期统一写为 `200`（业务错误码包装在响应体内）| 根据接口定义，错误码通过响应体 `code` 字段返回而非HTTP状态码；同时兼容服务端可能返回对应HTTP状态码的情况 |
| D-02 | 补充 TC-FILL-023~026 作为额外边界用例 | 仅覆盖需求表中最少用例数不足以发现边界缺陷，补充空路径、类型不匹配、评分越界、未发布访问等场景 |
| D-03 | TC-FILL-016 补充设备状态查询缺少参数的异常场景 | deviceId 为必填参数，缺失时的行为需要验证，FR-032 仅要求2条用例，此为第3条补充用例 |
| D-04 | 限流测试 TC-FILL-021 需在1分钟内连续发送11次请求 | 业务规则明确为"同一IP每分钟最多10次"，需在时间窗口内连续触发才能验证限流机制 |
| D-05 | TC-FILL-007 中缺少 deviceId 的预期错误码写为 `4001` | 接口定义中 `4001` 为"提交校验失败"，deviceId 缺失属于提交参数校验范畴 |
| D-06 | 所有测试用例均不携带 Authorization 或 Token 头 | 需求明确说明"H5填写接口无需登录（公开路径）"，因此请求中仅包含 Content-Type 头 |
