## TC-AUTH-001: 管理员使用正确账号密码登录-验证响应结构
- **关联需求**: FR-001
- **前置条件**: 管理员账号 admin 未被锁定，系统服务正常运行
- **测试步骤**:
  1. 发送 POST 请求到 `http://10.32.129.153:8082/api/auth/login`
  2. 请求Header: `Content-Type: application/json`
  3. 请求体: `{"username": "admin", "password": "admin123"}`
  4. 检查HTTP响应状态码
  5. 解析响应体JSON，验证各字段
- **预期结果**:
  - HTTP状态码: `200`
  - 响应体 `success` = `true`
  - 响应体 `code` = `200`
  - 响应体 `result.accessToken` 不为空，为非空字符串
  - 响应体 `result.refreshToken` 不为空，为非空字符串
  - 响应体 `result.expiresIn` = `28800`
  - 响应体 `result.tokenType` = `"Bearer"`
  - 响应体 `result.username` = `"admin"`
- **优先级**: P0
- **测试类型**: 正常流程

## TC-AUTH-002: 管理员登录成功-accessToken可用于鉴权接口访问

- **预期结果**:

  - 步骤5-6: HTTP状态码 `200`，响应不返回 `401` 未授权错误，说明Token有效可用于鉴权

## TC-AUTH-009: 账号锁定-连续5次错误密码后账号被锁定
- **关联需求**: FR-004
- **前置条件**: 管理员账号 admin 未被锁定，错误计数已清零，系统服务正常运行
- **测试步骤**:
  1. 循环执行5次：发送 POST 请求到 `http://10.32.129.153:8082/api/auth/login`，请求Header: `Content-Type: application/json`，请求体: `{"username": "admin", "password": "wrongpassword"}`
  2. 记录每次请求的响应状态码和响应体
  3. 第6次：发送 POST 请求到 `http://10.32.129.153:8082/api/auth/login`，请求Header: `Content-Type: application/json`，请求体: `{"username": "admin", "password": "admin123"}`（使用正确密码）
  4. 检查第6次请求的HTTP响应状态码和响应体
- **预期结果**:
  - 步骤1: 前4次响应 `code` = `401001`（用户名或密码错误）
  - 步骤1: 第5次响应 `code` = `401001` 或 `401002`（第5次错误触发锁定）
  - 步骤3-4: HTTP状态码 `401`，响应体 `success` = `false`，`code` = `401002`，提示"账号已锁定"
  - 即使使用正确密码，在锁定期间也无法登录
- **优先级**: P0
- **测试类型**: 边界条件

  3. 再次发送 POST 请求到 `http://10.32.129.153:8082/api/auth/login`，请求Header: `Content-Type: application/json`，请求体: `{"username": "admin", "password": "admin123"}`
  4. 检查HTTP响应状态码和响应体
- **预期结果**:
  - 步骤1: `code` = `401002`，确认账号处于锁定状态
  - 步骤3-4: HTTP状态码 `200`，响应体 `success` = `true`，`code` = `200`
  - 响应体 `result.accessToken` 不为空，登录成功
  - 说明账号锁定10分钟后自动解锁，可正常登录
- **优先级**: P1

## 测试执行注意事项

1. **执行顺序建议**: 先执行正常流程用例（TC-AUTH-001 ~ TC-AUTH-003），确保基础登录功能正常后再执行异常流程和边界条件用例。
2. **账号锁定测试（TC-AUTH-009）**: 执行后会导致 admin 账号被锁定10分钟，建议在所有其他用例执行完毕后最后执行，或执行后等待10分钟再继续执行其他用例。
3. **Token时效性**: TC-AUTH-010 需要等待10分钟验证自动解锁，建议在自动化执行中使用定时等待或手动调整Redis中的锁定时间戳。
4. **测试数据清理**: 每轮测试前确保 admin 账号错误计数已清零、无账号锁定状态、Token黑名单已清空。
5. **并发安全**: 避免多个测试实例同时使用 admin 账号执行测试，防止账号锁定计数互相干扰。
