# 问卷管理 - 测试用例

> **API基础地址**: `http://10.32.129.153:8082/api`
> **鉴权方式**: 所有接口请求Header中携带 `Authorization: Bearer {accessToken}`，accessToken通过 `POST /api/auth/login` 获取
> **管理员账号**: admin / admin123

## FR-008: 创建问卷

### TC-QN-001: 创建问卷 - 正常创建
- **关联需求**: FR-008
- **前置条件**: 已通过 `POST /api/auth/login` 获取有效accessToken
- **测试步骤**:
  1. 发送请求:
     ```
     POST http://10.32.129.153:8082/api/questionnaires
     Header: Authorization: Bearer {accessToken}
     Header: Content-Type: application/json
     Body: {"title": "员工满意度调查", "description": "2024年度员工满意度调查问卷"}
     ```
  2. 验证响应状态码和响应体
- **预期结果**:
  - HTTP状态码: 200
  - 响应体 `success` = `true`
  - 响应体 `code` = `200`
  - 响应体 `message` = `"创建成功"`
  - 响应体 `result.id` 不为空且为Long类型
  - 响应体 `result.title` = `"员工满意度调查"`
  - 响应体 `result.status` = `"draft"`
- **优先级**: P0
- **测试类型**: 正常流程

| 决策项 | 决策内容 | 理由 |
|--------|----------|------|
| 边界值用例补充 | FR-008新增TC-QN-004（标题恰好100字符） | 标题限制100字不仅需验证超限(101字符)，还需验证边界合法值(100字符)，确保上界行为正确 |
| 删除不存在问卷 | FR-012新增TC-QN-018（删除不存在的问卷） | 删除接口同样需要验证资源不存在的异常场景，与详情/更新保持一致 |
| 草稿空题目保存 | FR-014新增TC-QN-024（仅保存基本信息无题目） | 草稿保存应支持分步编辑，验证questions为空数组时系统行为正确 |
| 鉴权通用用例 | 新增TC-QN-027和TC-QN-028 | JWT鉴权是所有接口的前置要求，需独立验证未携带Token和无效Token两种场景 |
| 题目数据结构 | 草稿保存中使用type/title/options/required/sort字段 | 基于常见问卷系统的题目数据模型推断，包含单选题和文本题两种典型题型 |
| 复制后标题 | 预期新问卷标题与源问卷一致或包含"副本"标识 | 不同系统复制策略不同，采用兼容性预期描述 |
| 错误码对应HTTP状态码 | 404001对应HTTP 404，400009/400010对应HTTP 400 | 基于RESTful API设计惯例，错误码前缀与HTTP状态码对应 |
