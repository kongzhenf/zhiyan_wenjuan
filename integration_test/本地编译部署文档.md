# 本地编译部署文档 - 问卷调查平台

## 1. 前置要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Linux（推荐 Ubuntu 20.04+/CentOS 7+）或 macOS |
| Docker | >= 20.x |
| Docker Compose | >= 1.26（V1）或 >= 2.x（V2 插件） |
| 磁盘空间 | >= 5GB（镜像 + 数据卷） |
| 内存 | >= 4GB（建议 8GB） |

**无需安装任何编程语言环境**（JDK、Node.js 等全部在容器内通过多阶段构建完成）。

### Docker Compose 版本检测

```bash
# 优先检测 V2 插件形式
docker compose version
# 如果报错，再检测 V1 独立命令
docker-compose version
```

本文档使用 `docker-compose`（V1 形式），如果你的环境是 V2 插件，将命令中的 `docker-compose` 替换为 `docker compose`。

## 2. Dockerfile 说明（多阶段构建）

### 2.1 后端 API 服务（Java / Spring Boot）

**文件位置**：`code/后端/Dockerfile`

```dockerfile
# 多阶段构建 - 减小最终镜像体积
FROM maven:3.9-eclipse-temurin-17-alpine AS build
WORKDIR /app
COPY pom.xml .
RUN mvn dependency:go-offline -B
COPY src ./src
RUN mvn package -DskipTests -B

FROM eclipse-temurin:17-jre-alpine
WORKDIR /app
RUN addgroup -S appgroup && adduser -S appuser -G appgroup
RUN mkdir -p /app/exports && chown -R appuser:appgroup /app
COPY --from=build /app/target/*.jar app.jar
USER appuser
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

**设计决策**：
- Build 阶段：`maven:3.9-eclipse-temurin-17-alpine` 提供 Maven + JDK 17 编译环境
- 先复制 `pom.xml` 执行 `dependency:go-offline` 缓存依赖层，后续源码变更无需重新下载
- Runtime 阶段：`eclipse-temurin:17-jre-alpine` 仅含 JRE，镜像体积约 200MB
- 使用非 root 用户运行增强安全性

### 2.2 前端管理后台（Vue 3 / Element Plus）

**文件位置**：`code/前端/Dockerfile`

```dockerfile
FROM node:20-alpine AS build
WORKDIR /app
COPY package.json package-lock.json* ./
RUN npm install --registry=https://registry.npmmirror.com
COPY . .
RUN npx vite build

FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

**设计决策**：
- 使用 `npx vite build` 跳过 vue-tsc 类型检查（源码中存在类型级别兼容性提示，不影响运行时）
- nginx 配置中包含 `/api/` 反向代理到后端服务，前端通过相对路径 `/api` 调用 API
- 使用 npmmirror 国内镜像加速安装

### 2.3 H5 移动端（Vue 3 / Vant）

**文件位置**：`code/H5/Dockerfile`

```dockerfile
# H5 移动端问卷填写页面
FROM node:20-alpine AS build
WORKDIR /app
COPY package.json package-lock.json* ./
RUN npm install --registry=https://registry.npmmirror.com
COPY . .
RUN npx vite build

FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

**设计决策**：
- 与前端类似的多阶段构建
- nginx.conf 中添加了 `/api/` 反向代理指向后端服务

### 2.4 构建修复记录

| 问题 | 原因 | 修复方式 |
|------|------|----------|
| 前端 `npm run build` 失败 | vue-tsc 报 TS6196/TS2367 类型错误 | Dockerfile 中改用 `npx vite build` 跳过 TS 检查 |
| 后端启动报 `Unsupported character encoding 'utf8mb4'` | JDBC URL 中 `characterEncoding=utf8mb4` 不是 Java 标准编码名 | docker-compose.yml 中覆盖 SPRING_DATASOURCE_URL，改为 `characterEncoding=UTF-8` |
| 端口冲突 3306/6379/8080 | 宿主机已有其他容器占用这些端口 | MySQL 改用 3308、Redis 改用 6382、后端改用 8082 |

## 3. docker-compose.yml 说明

**文件位置**：项目根目录 `docker-compose.yml`

```yaml
version: '3.8'

services:
  mysql:
    image: mysql:8.0
    container_name: questionnaire-mysql
    environment:
      MYSQL_ROOT_PASSWORD: questionnaire123
      MYSQL_DATABASE: questionnaire_db
      MYSQL_CHARSET: utf8mb4
      MYSQL_COLLATION: utf8mb4_unicode_ci
    ports:
      - "3308:3306"
    volumes:
      - mysql-data:/var/lib/mysql
      - ./code/后端/db/init.sql:/docker-entrypoint-initdb.d/init.sql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 10s
      timeout: 5s
      retries: 10
      start_period: 30s
    command: --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci

  redis:
    image: redis:7-alpine
    container_name: questionnaire-redis
    ports:
      - "6382:6379"
    volumes:
      - redis-data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 5

  backend:
    build:
      context: ./code/后端
      dockerfile: Dockerfile
    container_name: questionnaire-backend
    ports:
      - "8082:8080"
    environment:
      MYSQL_HOST: mysql
      MYSQL_PORT: "3306"
      MYSQL_DATABASE: questionnaire_db
      MYSQL_USERNAME: root
      MYSQL_PASSWORD: questionnaire123
      REDIS_HOST: redis
      REDIS_PORT: "6379"
      REDIS_PASSWORD: ""
      JWT_SECRET: questionnaire-platform-jwt-secret-key-2024
      H5_BASE_URL: http://localhost:3001/s
      EXPORT_PATH: /app/exports
      SPRING_DATASOURCE_URL: jdbc:mysql://mysql:3306/questionnaire_db?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false
    volumes:
      - export-data:/app/exports
    depends_on:
      - mysql
      - redis
    restart: on-failure

  frontend:
    build:
      context: ./code/前端
      dockerfile: Dockerfile
    container_name: questionnaire-frontend
    ports:
      - "3000:80"
    depends_on:
      - backend

  h5:
    build:
      context: ./code/H5
      dockerfile: Dockerfile
    container_name: questionnaire-h5
    ports:
      - "3001:80"
    depends_on:
      - backend

volumes:
  mysql-data:
  redis-data:
  export-data:
```

### 服务编排说明

| 服务 | 镜像 | 宿主机端口 | 容器端口 | 说明 |
|------|------|------------|----------|------|
| mysql | mysql:8.0 | 3308 | 3306 | 数据库，挂载 init.sql 自动初始化 |
| redis | redis:7-alpine | 6382 | 6379 | 缓存服务 |
| backend | 本地构建 | 8082 | 8080 | Spring Boot API 服务 |
| frontend | 本地构建 | 3000 | 80 | 管理后台（nginx） |
| h5 | 本地构建 | 3001 | 80 | 移动端问卷填写（nginx） |

### 启动顺序

1. mysql / redis（无依赖，并行启动）
2. backend（等待 mysql 和 redis 就绪）
3. frontend / h5（等待 backend 启动）

### 网络通信

- 所有服务在 Docker 内部网络通过服务名通信（如 `mysql:3306`、`backend:8080`）
- 前端 nginx 通过 `proxy_pass http://backend:8080/api/` 代理 API 请求
- H5 nginx 通过 `proxy_pass http://backend:8080/api/` 代理 API 请求
- **禁止使用 localhost/127.0.0.1**：Docker 容器内的 localhost 是容器自身

## 8. 常见问题排查

### 端口冲突

如果启动时报 `port is already allocated`：

```bash
# 查看端口占用
docker ps --format '{{.Names}} {{.Ports}}' | grep <端口号>
# 或
netstat -tlnp | grep <端口号>
```

修改 `docker-compose.yml` 中对应服务的端口映射为未使用的端口。

### 镜像拉取失败

如果 Docker Hub 拉取慢或超时：

```bash
# 配置镜像加速（以腾讯云为例）
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<-'EOF'
{
  "registry-mirrors": ["https://mirror.ccs.tencentyun.com"]
}
EOF
sudo systemctl daemon-reload
sudo systemctl restart docker
```

### 后端容器启动失败

```bash
# 查看后端日志
docker-compose logs backend

# 常见原因：
# 1. MySQL 未就绪 → restart: on-failure 会自动重试
# 2. 环境变量配置错误 → 检查 docker-compose.yml 中的 environment
# 3. JDBC URL 编码问题 → 确保 characterEncoding=UTF-8（不是 utf8mb4）
```

### 数据库初始化失败

```bash
# 检查 MySQL 日志
docker-compose logs mysql

# 如果需要重新初始化：
docker-compose down -v  # 删除数据卷
docker-compose up -d    # 重新启动，会重新执行 init.sql
```

### Maven 编译失败

```bash
# 进入后端构建日志
docker-compose build backend 2>&1 | tail -50

# 如果依赖下载失败，可在 Dockerfile 中配置 Maven 镜像：
# 在 pom.xml 同级创建 settings.xml，Dockerfile 中 COPY 到 /root/.m2/
```

### 前端构建失败

```bash
# 查看构建日志
docker-compose build frontend 2>&1 | tail -50

# 如果 npm install 失败，检查网络或切换 registry
# 如果 vite build 失败，检查源码中是否有语法错误
```

### nginx 反向代理返回 502

```bash
# 检查后端是否正在运行
docker-compose ps backend

# 检查 nginx 配置中 proxy_pass 是否使用了服务名
# 正确: proxy_pass http://backend:8080/api/
# 错误: proxy_pass http://localhost:8080/api/

# 检查前后端是否在同一 docker network
docker network inspect 2052921194065797121_default
```
